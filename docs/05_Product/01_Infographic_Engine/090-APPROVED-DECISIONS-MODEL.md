# Approved Decisions Model

## Purpose

Store visual and behavioral decisions as reusable knowledge instead of leaving them inside prompts or generated HTML.

## Decision record

Every reusable decision should include:

- stable ID;
- category;
- scope;
- status;
- value;
- constraints;
- source;
- approval metadata;
- version;
- supersedes relationship when applicable.

## Categories

- brand;
- typography;
- color;
- spacing;
- grid;
- component;
- layout;
- anatomy usage;
- asset usage;
- content formatting;
- renderer behavior;
- QA threshold.

## Status values

- proposed;
- approved;
- deprecated;
- rejected.

## Approval principle

A proposed decision may be generated by GPT.

An approved decision requires explicit human approval.

## Versioning

Approved decisions are immutable within their version.

A later change creates a new version or a new record that supersedes the previous decision.

## Example

```yaml
id: DECISION-INFOGRAPHIC-000001
category: spacing
scope: infographic.global
status: approved
value:
  token: spacing.lg
constraints:
  min: spacing.md
  max: spacing.xl
source: manual_approval
version: 1.0
```

## Reuse

The renderer and schema should reference approved decision IDs or versioned token sets wherever possible.
